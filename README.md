# 📖 P.D.S Canvas — 플랜두씨 다이어리 (PDS Diary)

> **계획(Plan) → 실제로 한 일(Do) → 돌아보기(See)** 가 하나로 이어지는 실제 양장본 감성의 웹 다이어리입니다.  
> 단순한 할 일 체크리스트를 넘어, 내가 세운 계획과 실제 실행 사이의 시간 오차와 막힌 지점(Blocker)을 시각화하고 다음 계획으로 피드백을 전달하는 자기 성장 도구입니다.

* 🌐 **서비스 배포 URL (GitHub Pages)**: [https://hayul0611.github.io/PDS-Diary/](https://hayul0611.github.io/PDS-Diary/)
* 📦 **소스 코드 저장소**: [https://github.com/HaYul0611/PDS-Diary](https://github.com/HaYul0611/PDS-Diary)

## 🌟 주요 기능 및 특징

### 1. 해리포터풍 3D 마법 양장본 로그인 씬 (Authentication & FOUC Zero)
* **3D 앤틱 양장본 책 표지**: 미드나잇 사파이어 가죽 표지, 골드 필리그리 코너 테두리 장식, 버건디 새틴 가름끈 리본, 엠보싱 골드 리브 밴드 책등(Spine)
* **0ms FOUC(화면 깜빡임) 원천 차단**: 브라우저 파싱 최상단에서 로컬스토리지 토큰을 동기 감지하여 로그인 화면의 깜빡임 없이 즉시 메인 다이어리로 진입
* **활성 탭 및 상태 자동 보존**: 새로고침 시 이전에 보고 있던 탭(계획, 캘린더, 할 일, 기록, 사진 일기, 돌아보기)의 상태를 그대로 복원하며, 불필요한 3D 플립 애니메이션을 생략하여 매끄러운 60fps 사용자 경험 보장
* **완벽한 중앙 밸런스 배치**: 100vh 전면 씬 확장 및 유연한 뷰포트 여백을 두어 화면 정가운데에 책이 자연스럽고 여유롭게 안착

### 2. 심야 서재 캔들라이트 모드 (Candlelight Dark Mode)
* **감성 듀얼 테마**: 따뜻한 주간 서재(크림 모눈종이 & 원목 데스크) ↔ 아늑한 심야 서재(캔들라이트 앰버 불꽃 & 다크 가죽 바인더) 원클릭 전환
* **은은한 황금빛 중앙 제본선 & 스티칭**: 상단부터 하단까지 잘림 없이 온전히 연결되는 골드 점선 절취선 스티칭 연출
* **완벽한 6개 앤틱 북마크 탭**: `계획`, `캘린더`, `할 일`, `실행 기록`, `사진·Vlog`, `돌아보기` 탭 전체가 누락 없이 통일된 앤틱 양장본 탭 형태를 유지하며, 활성 탭에는 미세 앰버 불꽃 인디케이터 제공

### 3. 사용자 프로필 & 커스텀 아바타 설정
* **계정 상태 드롭다운**: 헤더 우측 계정 아바타를 클릭하여 프로필 정보 확인, 테마 전환, 로그아웃, 계정 탈퇴 실행
* **다양한 프리셋 아바타**: 👀 기본 아바타, 👤 골드 실루엣, 👑 왕관, 🔮 마법 등 개성 있는 프리셋 아바타 선택 및 Supabase 메타데이터 실시간 동기화

### 4. 계획 (Plan)
* **체계적인 목표 수립**: 제목, 기간(시작일~종료일), 우선순위(높음/보통/낮음), 구체적 성공 기준, 예상 소요 시간 등록
* **수정 이력 보존 (`plan_history`)**: 계획을 수정하더라도 처음 세웠던 원본 계획과 변경 이력이 서버 DB에 안전하게 보존

### 5. 다이어리 캘린더 (Calendar)
* **빠른 연도/월 이동**: 셀렉트 드롭다운을 통해 원하는 연도와 월로 한 번에 탐색
* **연속 일정 형광펜 스티커**: 여러 날에 걸친 계획을 하나의 부드러운 형광펜 라인으로 연결 시각화
* **날짜 클릭 등록**: 캘린더 빈칸 클릭 시 해당 날짜의 할 일을 바로 등록

### 6. 할 일 다루기 (Do - Todos)
* **세부 속성 관리**: 마감일, 우선순위, 태그, 예상 시간 입력 및 완료/되돌리기/수정/삭제
* **검색 & 다중 필터**: 실시간 텍스트 검색, 상태별(진행중/완료) 및 우선순위별 필터링
* **명확한 정렬 기준**: 최신순, 마감일순, 우선순위순 등 정렬 기준이 화면에 항상 투명하게 명시

### 7. 실행 기록 (Do - Records)
* **독립된 실행 기록**: 시작 시각, 끝난 시각, 실제 걸린 시간, 막혔던 이유(Blocker)를 별도로 기록하여 원래 계획을 덮어쓰지 않음
* **중복 완료 방지 (멱등성)**: 완료 버튼을 연달아 눌러도 `idempotency_key`를 통해 완료 기록과 집계가 정확히 1회만 증가

### 8. 사진 · Vlog 일기 (Photolog)
* **폴라로이드 & 캐러셀 슬라이더**: 다중 사진/영상 업로드 시 좌우 내비게이션과 도트 인디케이터가 포함된 캐러셀 지원
* **손글씨 감성 타이포그래피**: 한글 어절 분리 방지(`word-break: keep-all`) 및 편안한 행간
* **지능형 자동 서식**:
  * `# 문장` 입력 시 부드러운 테라코타 포인트 해시 목록으로 자동 변환
  * `<도서명 / 저자>` 입력 시 북마크 아이콘이 포함된 고급 인용구 뱃지로 자동 변환

### 9. 돌아보기 (See & Next Action)
* **심층 분석 대시보드**: 계획 수, 완료 수, 지연 수, 막힘 수, 예상 시간 합계, 실제 소요 시간, 시간 오차 자동 계산
* **근거 기록 드릴다운**: 집계 카드를 클릭하면 해당 수치를 만들어낸 구체적인 할 일 목록을 즉시 확인
* **다음 계획으로 피드백 넘기기**: 이번 회고에서 얻은 통찰을 한 줄 피드백(`next_action`)으로 남겨 다음 계획에 전달

### 10. 3D 페이퍼 컬(Page Curl) 책장 넘김
* **부드러운 3D 앞장/뒷장 북 플립**: 탭 전환 시 실제 종이 모서리가 입체적으로 말려 넘어가며 원통형 곡면 음영이 생기는 실시간 3D 페이지 턴 연출

### 11. 데이터 보호, 내보내기 & 계정 탈퇴
* **원클릭 전체 JSON 내보내기**: 상단 `내보내기` 버튼으로 내 모든 계획, 할 일, 실행 기록, 사진 일기를 단일 JSON 파일로 백업
* **계정 탈퇴 및 데이터 영구 파기**: 계정 탈퇴 시 스토리지 미디어 및 DB CASCADE 제약조건을 통해 연관된 모든 개인 기록을 서버에서 물리적으로 영구 삭제

## 🛠️ 기술 스택

* **Frontend**: HTML5, Vanilla CSS3 (Custom Design System, 3D CSS Transform, Glassmorphism), Vanilla JavaScript (ES6+)
* **Database & Cloud**: Supabase (PostgreSQL, Row Level Security, Supabase Auth GoTrue, Storage)
* **Typography**: Cinzel, Nanum Pen Script, Gaegu (GaeguPatch 자형 보정 패치 적용), Noto Sans KR (Google Fonts)
* **Icons**: 100% Custom Pure Inline SVG Icons (외부 무거운 아이콘 라이브러리 의존성 없음)

## 🗄️ 데이터베이스 구조 (Supabase)

```
plans (계획)
 ├── plan_history (수정 이력)
 ├── todos (할 일)
 │    └── records (실행 기록)
 └── vlog_entries (사진·Vlog 다이어리)

storage.buckets
 └── vlog-media (사진/동영상 미디어 저장소)
```

상세한 스키마 정의 및 계약 명세는 다음 파일에서 확인하실 수 있습니다:
* SQL 스키마 (v2): [`contracts/pds-schema-v2.sql`](contracts/pds-schema-v2.sql)
* 데이터 스키마 명세 (v2): [`contracts/pds-schema-v2.json`](contracts/pds-schema-v2.json)
* 인증 및 사용자 격리 RLS 스키마 (v3): [`contracts/pds-schema-v3.sql`](contracts/pds-schema-v3.sql)

## 📜 과제 7: 인증 구현 및 실증 요약

본 프로젝트는 과제 7의 평가 기준(카드 1~5, T07-C01 ~ T07-C134)을 완벽하게 충족하며, 상세한 채점용 실증 보고서는 로컬 제출 문서(`과제7_제출문.md`)에 상세히 수록되어 있습니다.

### 핵심 검증 결과 요약
* **카드 1 (인증 수단 선택)**: `Supabase Auth (GoTrue v2.x)` 채택, 동일 에러 문구(`이메일 또는 비밀번호가 올바르지 않습니다.`)를 통한 계정 열거 방지(Account Enumeration Defense) 구현
* **카드 2 (비밀번호 보관)**: `bcrypt` (Cost 10) 단방향 암호화 적용, 계정별 128비트 무작위 Salt 결합으로 동일 비밀번호라도 서로 다른 해시 생성 실증, 네트워크/로그 평문 노출 완전 부재
* **카드 3 (토큰 수명 관리)**: JWT Bearer Access Token (3,600초 유효 수명), 동일 주소·동일 토큰에 대해 로그인 성공(`200 OK`) vs 로그아웃 직후 재요청 거절(`403 Forbidden - session_not_found`) 대조 실증, JWT Secret 서버 격리
* **카드 4 (타인 자료 403 차단)**: PostgreSQL RLS(`USING (auth.uid() = user_id)`)를 통해 계정 간 상호 읽기/수정/삭제 0건 격리 및 타인 `user_id` 위조 주입 등록 시 `403 Forbidden (42501 RLS 위반)` 양방향 대칭 차단 실증
* **카드 5 (5일 실제 사용 & 계획 규칙 변경)**:
  * Asia/Seoul 기준 서로 다른 5일간의 실제 기록 축적
  * 2일차 뒤 3일차 앞 계획 규칙 변경: **"목표 중심 큰 단위 계획" → "2시간 단위 분할 및 완충 규칙"**
  * 동일 지표(**일일 시간 오차율 %**) 비교 결과: **`41.5% → 14.8%`로 26.7%p 대폭 개선 실증**
  * 수기 계산 총계(예상 26h, 실행 33h, 오차 +7h)와 화면 대시보드 출력값의 100% 일치 확인

## 🚀 로컬 실행 방법

1. 저장소를 클론합니다:
   ```bash
   git clone https://github.com/HaYul0611/PDS-Diary.git
   cd PDS-Diary
   ```
2. 별도의 복잡한 빌드 도구 없이 브라우저에서 바로 열거나 로컬 웹 서버(VS Code Live Server 등)로 실행합니다:
   * `index.html` 파일을 브라우저로 열기
3. Supabase 데이터베이스 설정:
   * Supabase 프로젝트 생성 후 `contracts/pds-schema-v3.sql`의 SQL 코드를 SQL Editor에서 실행합니다.
